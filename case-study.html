Turning Disorganized Discord Game Nights into a Self-Balancing, Data-Driven 5-Stack Platform

Organizing 5-player League of Legends sessions among working adults fails for two reasons: coordination friction (noisy Discord pings, unclear quorum rules, and awkward 6th-player benching) and biased post-game feedback (raw KDA scoreboards that undervalue frontline tanks, roam supports, and splitpushers). I designed and built an end-to-end Discord bot, automated Riot Match-v5 telemetry pipeline, and modular analytics web hub to solve both.

1. Problem Statement & Product Discovery

Before writing code, I audited the recurring failure modes in our 10-player Discord server (#5-stackers) across scheduling, lobby management, and post-match retention:

📉 1. The "5-or-Bust" Dropoff Trap

Traditional scheduling polls expire or cancel if 5 players aren't reached, killing viable 2-, 3-, or 4-player Flex nights. Conversely, when 6+ players want to play, manual benching creates social awkwardness.

🔔 2. Notification Fatigue in Discord

Posting a new message for every RSVP, role change, reschedule, or lookup buries active session cards and causes squad members to mute the coordination channel.

⚖️ 3. Misaligned Match Analytics

Public sites like OP.GG mix solo queue games with random strangers alongside organized 5-stack games, and naive KDA formulas punish sacrificial engage supports and macro splitpushers.

2. Product Design & Behavioral UX Architecture

🔄 Quorum Viability & Auto-Promotion State Machine

Sessions never auto-cancel below 5 players; 2–4 confirmed starters remain viable for Duo/Trio/Flex, while 5 starters unlock full Weekend Ranked 5s detection (Fri–Sun 8 PM–1 AM local time). Players 6–10 enter a FIFO Bench Substitute Queue. If any starter clicks Can't Make It, Bench #1 is atomically promoted and notified.

🔕 Anti-Noise "Living Card + Attached Thread" Pattern

To keep #5-stackers clean and scannable, I separated persistent status from real-time notifications:

❌ Legacy Bot Pattern
  • 15+ separate messages per game night
  • Public slash command spam from stats lookups
  • Outdated embeds buried 2 screens up
✅ Living Card + Thread Architecture
  • Exactly 1 Session Card edited in-place for all RSVPs & W-L updates
  • 1 Attached Thread for targeted pings & match recaps
  • 4 Living Synergy Threads edited in-place + ephemeral-by-default lookups
💡 Closed-Loop Product Feedback Pipeline

Users report friction or propose features either directly inside Discord via /feedback (and the 💡 Feedback button on every session card) or through the Web Dashboard's Feedback Builder. github_tickets.py validates per-user rate limits, structures metadata, and creates labeled GitHub Issues via the GitHub REST API (or authenticated gh CLI).

3. Data Science, Rating Engine & Decision Support Methodology

🧮 De-Biasing Evaluation: 55% Role + 45% Kit Archetype Blending

Using Riot Match-v5 participant telemetry and challenges sub-metrics (CC time, effective healing/shielding, saveAllyFromDeath, turret plates, void monsters), rating_engine.py scores 6 normalized pillars and dynamically blends weights based on where a player played (55%) and what champion kit they piloted (45%):

Weight[pillar] = 0.55 × Role_Weight[pillar] + 0.45 × Archetype_Weight[pillar]
Rating = clamp(Weighted_Mean(Pillars) − Death_Liability + Outcome_Adj, 15.0, 99.5)

Result: A Lulu Support going 1/1/26 with 11.4k shielding and 2.35 vision/min competes fairly for Match MVP alongside a 14-kill Jinx, and off-meta flex picks (e.g., Tank Top vs Splitpusher Top) are benchmarked against realistic kit expectations.

📊 Empirical Bayes Shrinkage for Small-Sample Synergy Stabilization

In recreational squad datasets, a duo going 1W-0L (100% raw win rate) would otherwise outrank a proven 14W-6L (70% WR) partnership. To eliminate small-sample noise across the 4 map partnerships (Bot+Sup, Mid+Jng, Top+Jng, Sup+Jng), I implemented a 5-game Bayesian confidence ramp toward a 50% prior plus a MIN_SYNERGY_GAMES = 3 leaderboard threshold:

c = min(1.0, games / 5.0)
Bayesian_WR = (c × Raw_WR) + ((1 − c) × 50.0)
Synergy = 0.42×Bayesian_WR + 0.24×Duo_Rating + 0.14×Coord + 0.20×KDA_Norm

Result: Proven 5+ game partnerships with strong joint CC/objective coordination anchor S-Tier slots, while 1-game flukes stay dampened near the 50% baseline.

🧠 Combinatorial Decision Support: 5-Stack Lineup & Role Optimizer

When 5 friends with overlapping role preferences (e.g., two Mid mains and zero Top mains) ready up, assigning lanes manually leads to suboptimal flex picks and broken duo chemistry. The Squad Builder solves all 5! = 120 lane permutations in-browser, maximizing 58% Role Proficiency (historical role-specific rating + primary/secondary comfort) + 42% 4-Pair Map Synergy across Bot+Sup, Mid+Jng, Top+Jng, and Sup+Jng.

4. Hybrid System Architecture & Privacy-Preserving Deployment

To showcase real production data on GitHub Pages without exposing the home Synology NAS to public internet traffic or leaking private Discord/Riot identifiers, the system uses a decoupled, match-triggered static publishing pipeline:

1. Synology NAS Docker
Runs bot.py 24/7 via Container Manager; polls Riot Account-v1 & Match-v5 APIs and persists data/league_stats.json.
2. Privacy Sanitizer
export_dashboard.py strips Discord snowflake IDs (id, creator_id, channel_id, thread_id) and immutable Riot puuid tokens.
3. Match-Only GitHub Push
Only when new matches are recorded (/sync-matches, /log-match, or auto-tracker), the bot updates data/live_payload.json on the gh-pages branch via GitHub Contents API.
4. Modular ES Dashboard
GitHub Pages serves clean Vanilla ES Modules (web/js/*.js), defaulting to Demo Preview for portfolio visitors with one-click switching to Live Data.
